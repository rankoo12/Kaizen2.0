## 3. Deep dives

### 3.1 Migrate off gpt-4o / gpt-4o-mini (High, adopt)
- **Facts:** All three 4o snapshots shut down **Jan 14 2027**, and `gpt-6-luna` is the official replacement ([OpenAI](https://developers.openai.com/api/docs/deprecations)). Luna costs $0.10 in / $0.50 out, $0.01 for cached input, and supports structured outputs, tools and vision ([inference.net](https://inference.net/models/gpt-6-luna.md)). `text-embedding-3-small` is **not** deprecated ([OpenAI forum](https://community.openai.com/t/deprecation-notice-upcoming-model-shutdowns-in-2026/1379553)), so pgvector embeddings are safe.
- **In the code:** `model-tier.ts` defaults `MINI_MODEL='gpt-4o-mini'` and `FRONTIER_MODEL='gpt-4o'`. `openai.gateway.ts` bypasses the tier and hard-codes `gpt-4o-mini` for `compileStep` (l.135/226) and `resolveElement` (l.284/316). Those must change in code, not only in env.
- **Plan (~1 day):** (1) route both calls through `getModelForTier()`; (2) set the mini default to `gpt-6-luna`, and pick a frontier option (`gpt-6.1-terra` at $1/$5 is the cheap one, [pricing](https://tech-insider.org/gemini-vs-gpt-argon-vs-terra-api-price-dec-1-2026/)); (3) run the bench campaign with judge-lite and compare FALSE-PASS, token trajectory and L5 accuracy against the 4o baseline; (4) fix the metadata `model:` strings so token accounting stays correct.
- **Risk:** prompts tuned on 4o (e.g. the testwriter judge examples) may behave differently. Re-check must-fail probes. Don't wait until December: OpenAI gave only 92 days' notice on this one.

### 3.2 Playwright 1.58.2 → 1.65 (High, prototype)
- **Breaking change that hits you:** in 1.65, unrendered text (unslotted shadow content, a closed `<details>`) no longer counts toward accessible names or `ariaSnapshot()` ([notes](https://playwright.dev/docs/release-notes)). `dom-pruner` overwrites `accessibleName` from `ariaSnapshot()` precisely so that the cached `role=X[name="Y"]` strings match. After the upgrade, some stored names will stop matching, which means cache misses and a burst of heals on shadow-DOM and accordion-heavy sites (Buzzly, the nightmare site).
- **Wins:**
  - `ariaSnapshotJSON()` (1.63) replaces the regex YAML parser `parseAriaSnapshotName()`.
  - Today the pruner calls `ariaSnapshot()` **once per candidate** in a loop. One page-level `ariaSnapshot({mode:'ai'})` plus `page.getByRef('e12')` (1.64) could replace both the N round-trips and the `data-kaizen-id` injection. 1.65 also fixed container names (dialog, navigation, table) being dropped in AI mode ([issue](https://github.com/JustasMonkev/mcp-accessibility-scanner/issues/325)).
  - `locator.visible()` and `locator.within()` (1.63/1.64) help L0–L2 disambiguation (issue 5).
  - Actions now wait for elements to stop being inert, which helps with modal stacks.
  - `frameLocator()` with no selector searches all frames.
  - `page.content()` serializes shadow roots.
  - Proxy credentials no longer leak to sites that return 401.
- **Plan (2–3 days):** bump `playwright` and all `mcr.microsoft.com/playwright:v1.58.2-noble` images together. The `^1.49.1` range would let a lockfile regen jump to 1.65 while Docker stays at 1.58, so pin the version explicitly. Then run a hot-phase bench (expect 0 LLM tokens) and treat any token spend as name drift. Add a one-off migration that re-derives names for cached rows whose selector no longer matches, rather than letting them decay. Do the `mode:'ai'`/`getByRef` refactor of the pruner as a separate step after that.
- **Risk:** medium. 1.65 also changes cookie matching to RFC 6265 and how class fields compile (`useDefineForClassFields`). Run the full 1,240-test suite.

### 3.3 Agent-memory lessons → Mission 3 / issue 8 (Medium, design input)
- **The post's findings** ([Anthropic](https://www.anthropic.com/research/components-of-agent-memory)):
  - Store only knowledge the agent derived itself, with its evidence and known traps.
  - Run an offline "dreaming" pass that re-checks notes against the original transcripts and fixes them. Wiki+search scored 61% vs 53% for search alone, and saved ~20k tokens per question.
  - Keep the always-loaded layer small.
  - "Record only failures" lowered gains, by 0.23 for Opus 5.
- **Mapping to Kaizen:**
  - A nightly consolidation job (BullMQ cron) could replay the day's `step_results` and heal provenance, re-validate selectors before promoting them to the shared pool, and prune them. That is the "crawler validation" path in issue 8, driven by evidence instead of a vote threshold.
  - For per-app SKILL.md files, keep the always-loaded part short, keep one page per app area, and record successes as well as heals.
- **Rec:** fold these into the Mission 3 spec. There's no library to adopt.

### 3. Deep dives

#### A. Decisions API for L5 (High, prototype)
- **Request shape:** `{model:"gpt-6-luna", input, questions:[{type:"choice", name, instructions, choices:[{value, description}]}]}`. The response gives `choice`, `probabilities[]` and `confidence` ([guide](https://developers.openai.com/api/docs/guides/decisions)).
- **Limits:** `gpt-6-luna` only, 1–400 questions per request, and caching needs a shared prefix of at least 1,024 tokens. The docs give **no stated maximum on `choices`**, so test it with 50+ pruned candidates.
- **Fit:**
  1. **Per step:** the pruned candidates become `choices`, with `value=data-kaizen-id` (or the `getByRef` ref after Playwright 1.65) and `description` = role, name and nearby text. Feed `probabilities[top]` into the initial cache confidence, and treat a low top-1/top-2 margin as "ambiguous". That margin could replace the separate disambiguation call in issue 5.
  2. **Batch:** at compile time, put every L5-bound step of a test into one request as up to 400 questions that share the page snapshot as the cached prefix. That's one round trip per page instead of one per step.
- **Effort:** ~1–2 days as a new `DecisionsResolver` behind the gateway interface, with a per-tenant flag. Bench it against the current resolver and against Haiku 5.5 on L5 accuracy, latency and $ per heal.
- **Risk:** single-vendor, single-model. Keep the Responses path as the fallback.

#### B. Node 20 → 24 (High, adopt)
- **Change:** swap the `FROM node:20-*` lines in 5 Dockerfiles for `node:24-*`, set `ci.yml` to `node-version: 24`, and set engines to `>=22`.
- **Workers:** check what Node the `mcr.microsoft.com/playwright:v1.58.2-noble` images bundle. Bumping Playwright to 1.65 (deep dive 3.2 above) refreshes those images anyway, so do both in one infra PR.
